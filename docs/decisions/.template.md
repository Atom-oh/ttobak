# ADR-NNN: Topic

- Status: Accepted | Proposed. Name any former ADR numbers this record consolidates.
- Implementation checked: YYYY-MM-DD, against code, tests and configuration.

## Decisions

State each rule in force today, grouped by sub-topic. One rule per bullet, with
the reason when it is not obvious. Keep security, privacy, retention and
concurrency rules explicit, with the exact scope of any exception.

## Not implemented or off by default

List decided parts that are absent, staged or behind a flag, and what must hold
before they are enabled.

## Limits and accepted risks

Residual risks the owner accepted, with dates for owner decisions. Documenting a
risk does not fix it. When records are merged, every accepted risk and known gap
of the earlier records is carried over unless code has closed it.

## Source

The files and symbols that own this topic. No line numbers. Only code, tests
and configuration are evidence; a source comment or IaC alone does not prove a
security guarantee or the deployed state.

Write concise English-only prose. A record describes the current decision, not
its history: when a decision changes, rewrite the affected bullets in place and
let version control keep the old text. Do not append dated amendments, per-PR
rollout notes, API specifications or runbook steps.
