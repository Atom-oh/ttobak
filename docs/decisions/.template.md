# ADR-NNN: Decision Title

- Status: Proposed | Accepted | Deprecated | Superseded by ADR-NNN.
- Decision date: YYYY-MM-DD, or explicitly state that the original date was not recorded.
- Implementation checked: YYYY-MM-DD, when checked against code/tests.

## Context

State the concrete problem and constraints at the time of the decision.

## Decision and rationale

State the chosen approach and why it addresses the problem. Keep historical
choices separate from current requirements. Link relevant superseding ADRs.

## Current implementation

Describe behavior verified in code/tests. Separate implemented behavior, original
plans, remaining gaps, and live deployment facts. Do not infer deployment from
IaC alone or turn a source comment into proof of a security guarantee.

## Alternatives and consequences

Summarize material alternatives, benefits, costs, and accepted residual risks.
Preserve explicit security policy and the exact scope of accepted exceptions.
Describe unresolved contradictions without granting a new policy exception.

## Evidence and open questions

Link repository source, tests, and related ADRs. Name the symbols or behaviors
that support the decision and any assumptions requiring verification.

Write concise English-only prose. Keep executable literals unchanged; explain
language-specific behavior in prose instead of inventing translated examples.
Do not duplicate full API specifications, old implementation plans, or runbooks.
