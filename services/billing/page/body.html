                              데이터 탐색

                              COT의 원본 시트를 그대로 검색·필터·집계합니다. 필터와 그룹을 고른 뒤 원본·집계·차트로 보고 CSV로 내려받을 수 있습니다. 위의 법인 선택을 따르며, "전체 법인"을 켜면 볼 수 있는 법인을 모두 합칩니다.

                              이 대시보드를 만드는 방법

                              숫자는 코드가 계산합니다. Bedrock 에이전트는 계산된 데이터셋만 읽고 해석·다음 행동·고객 질문을 쓰며, 문장 속 숫자·날짜·이름이 그 데이터와 맞는 문장만 화면과 보고서에 올립니다.

                              1. 수집·정규화: COT.zip(법인별 Template·COH·COT360.html)을 풀고 xlsx2csv.py로 "Data *" 시트를 CSV로 바꾼 뒤, raw_export.py가 시트마다 법인·월·차원(keys)·비용·사용량으로 정규화합니다. "데이터 탐색" 탭의 원본이 이것입니다.
                              2. 영역별 분석(병렬): ec2_types.py(인스턴스 유형×월×구매 옵션), accounts.py(연결 계정 추이 + COH 리소스), tag_services.py(태그 → 서비스 이름), 서비스·Bedrock·약정·데이터 전송 집계를 각각 따로 계산합니다.
                              3. 태그·워크로드 연결: 리소스 태그를 EKS 클러스터 → project/service → team 순으로 서비스 이름으로 바꾸고, 계정·인스턴스 유형·리전과 이어 붙입니다. 생성일 태그(…/created-at)로 기간의 최근 3개월에 새로 생긴 워크로드를 표시합니다.
                              4. 시장조사: 분석에서 나온 신호(예: 특정 클러스터·계정, Bedrock 급증)로 AWS What's New·블로그와 동종업계 채택 사례를 웹 검색하고, 출처를 확인한 항목만 남깁니다. What's New는 매일 00:30(KST)에 자동 수집합니다.
                              5. COT360 지표 흡수: cot360_metrics.py가 COT360 페이지에 내장된 계산 결과(단위 지표, Graviton·구세대 대상, 주말 탄력성, SP·RI 인벤토리, SP 구매 권고, 스토리지 계층, COH 액션 요약)를 데이터셋으로 옮기고, COH 리소스 권고를 태그 워크로드별로 다시 묶습니다.
                              6. 인사이트·브리핑 생성: insights.py가 영역별 문장을, briefing.py가 법인별 실행 항목(무엇·얼마·담당·다음 행동·근거 탭)과 법인 벤치마크를 규칙으로 만듭니다. 서로 다른 데이터를 잇는 항목이 COT360에 없는 부분입니다. 예: 만료 예정 EC2 Instance SP의 계열 × Graviton 전환 대상, 법인 간 vCPU 단가 차이, SP 구매 권고와 만료분 갱신을 함께 계획하는 것.
                              7. 에이전트 해석: agents.py가 법인마다 영역 에이전트 4개(약정·현대화·성장·지출)를 병렬로 돌린 뒤 종합 에이전트 1개가 요약, 실행 항목별 구체적 다음 행동과 고객 질문, 영역 간 연결을 씁니다. 모델은 내부 계정 Bedrock의 Claude Sonnet 5.5(global 교차 리전 추론, 한국 밖 리전에서 처리될 수 있음)이고, 입력은 코드가 만든 법인별 요약 데이터뿐입니다(다른 법인 데이터 없음). 검증기가 문장 속 금액·비율·건수·날짜·식별자를 그 에이전트가 받은 입력과 대조해 맞지 않는 문장은 버리고, 다른 법인 이름이 들어간 문장도 버립니다. 입력이 같으면 캐시된 응답을 다시 쓰므로 결과가 같습니다. 보고서(report.py)는 같은 데이터셋으로 자동 생성됩니다.
                              8. 검증: 법인별 최근 월 합계 = COT360 KPI, COH 절감 = HTML 값, 계정 합계 = KPI(차이 $0.41 이하), EC2 유형 합계 = 서비스 비용(차이 1.3% 이하), 서비스별 태그 합계 = COH 합계. COT360 페이지의 현대화 절감 추정·주말 탄력성 절감·다음 SP 만료일과 같은지도 확인합니다(모든 법인 $1 이내 일치).
                              9. 배포·권한: 데이터는 비공개 S3에 두고, TTOBAK 로그인 후 TTOBAK account에 직접 멤버로 연결된 법인 데이터만 서버에서 걸러 내려줍니다.

                              COT 데이터로 알 수 없는 것

                              • COT 기간: —
                              • CUR: —
                              • 시트가 한 가지 기준(서비스, 계정, 인스턴스 유형)으로만 나뉘어 있어 "계정 × 인스턴스 유형" 같은 교차 추이는 없습니다. 계정별 유형·태그는 COH 권고 리소스(월 추정액)로만 보입니다.
                              • 태그는 COH 권고 리소스에만 있고, COH가 꺼진 법인은 태그가 없습니다.
                              • Bedrock은 modelId·호출 단위가 아니라 Marketplace 상품·사용 유형 단위입니다.
                              • 신사업·조직 해석(예: 신규 사업·해외 거점)은 빌링 신호와 공개 보도를 맞춘 가설이므로 고객 인터뷰로 확인해야 합니다.
